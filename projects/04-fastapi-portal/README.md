# 本地整合门户

> 用一个 FastAPI 本地门户，把散在 15 个文件夹里的自建项目接进来；
> 子项目零改动（运行时注入），并给产物加了 8 道自动检查。
>
> 代码不公开：含个人档案与本地绝对路径，仅在此说明做法。

## 背景与目标

- 场景：15 个自建项目散在 15 个文件夹，每次找资料都要翻一遍
- 原来的做法：靠记忆和资源管理器
- 痛点：入口分散；改了一处数据，其他材料忘了重出
- 目标：一个入口进所有项目；数据改一处，产物全部联动

## 我做了什么

- 需求拆解：统计访问频率 → 排入口顺序 → 接子项目 → 加产物检查
- 方案：本地 FastAPI 门户 + 运行时注入，子项目代码零改动
- 关键实现：路由分三类——首页 `/`、子项目原样托管 `/p/<文件夹>/<路径>`、外部静态工具只读挂载 `/ext/<id>/<路径>`
- 关键实现：子项目里的相对链接（`../大学编年史/xxx.html`）靠 `/p/<同名文件夹>/` 映射保持可用；HTML 返回时注入一个「回门户」悬浮层，不落盘改文件
- 关键实现：数据单一真源，一份源出多份产物
- 关键实现：8 道自动检查——数据一致性、打印版式、页面溢出、产物新鲜度等，任一道红就不出稿
- 运行边界：只绑 `127.0.0.1`，本机自用；GZip 压缩静态响应

## 结果

- 整合 15 个子项目，入口顺序按使用频次排
- 改一次档案数据，十余份评优材料全部重出（不再手工同步）
- 8 道检查复跑全过才出稿

> 为什么不公开代码：`projects.json` 里写死了本地绝对路径，门户还会读到奖项、档案等个人数据，并引用 15 个私人子项目。脱敏成本高，而这一页想说清楚的是「怎么把散落的东西收进一个入口」，代码本身不是重点。

## 技术栈

- Python / FastAPI + uvicorn
- `templates\` + `static\`：页面模板与前端资源
- SQLite（结构化数据）+ `projects.json`（子项目清单）
- markdown、pypdf：材料预览与页数统计
- Windows 批处理：一键启动 / 手机同 WiFi 访问
